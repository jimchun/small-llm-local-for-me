1. 项目概述

1.1 项目定位

本项目是一套轻量化本地 AI 产品化方案，采用「本地微型推理核 + 联网权威知识库」的混合架构，解决通用大模型的三大痛点：

  • AI 幻觉：所有事实知识均来自权威数据源（维基百科、国家标准、政策库），模型仅负责逻辑推理，不生成编造事实
  • 知识过期：知识库实时联网更新，无知识截止日期限制
  • 部署门槛高：消费级笔记本（8GB 内存）即可运行，无需高端显卡

1.2 架构核心理念

用户提问 → 小模型判断「是否需要查资料」
         → 生成检索关键词/查询语句
         → 联网拉取权威原文
         → 小模型基于新鲜资料做推理、总结、作答
✅ 架构优势
  • 本地模型尺寸极小（1.5B），硬件门槛极低，几百 MB 即可运行
  • 知识永久新鲜，无静态幻觉，联网实时查询权威源
  • 省去预训练/微调注入知识的巨大成本，知识库独立维护
  • 本地推理核无需存储海量知识向量，存储压力小

1.3 与 AGI 的关系

⚠️ 架构定位：工具增强型窄智能

本架构属于成熟轻量化智能落地路线，不等于完整 AGI。核心短板：

  • 断网后完全丧失事实问答能力，基础常识也需要联网查询
  • 无法沉淀隐性知识，高频问题重复检索，不会自主记忆简化思考
  • 极小模型逻辑容量有限，长链条复杂推理存在性能上限
  • 仅被动响应用户问题，无自主探索、主动验证猜想的智能闭环

基于 DeepSeek-R1-Distill-Qwen-1.5B Q4_K_M 量化：

运行模式生成速度首 Token 延迟适用场景

💡 实际体验

人类阅读速度仅 5~8 t/s，本机纯 CPU 输出速度远超阅读速度，全程流畅无等待感。32GB 内存完全冗余，模型+系统+检索工具总占用不超过 8GB。

3. 核心模型选型

3.1 本地推理核（两级梯队）

模型参数量化大小定位特点
DeepSeek-R1-Distill-1.5B 1.5B ~1GB (Q4) ✅ 本项目首选 强思维链 CoT，多源资料交叉对比，Apache 2.0

Needle 26M ~60MB 纯调度层 仅输出检索指令，需搭配第二层模型

3.2 落地组合方案

方案 A：单模型一体化（推荐新手）

仅使用 DeepSeek-R1-Distill-1.5B，完整处理：提问 → 检索判断 → 联网拉取 → 推理总结全流程。Ollama 一键部署，代码逻辑简单。

方案 B：双层分离架构（极致省资源）
  • 第一层：Needle 26M（常驻后台）— 判断是否联网、生成检索关键词
  • 第二层：MiniCPM5-1B（按需加载）— 接收原文做逻辑梳理、交叉验证、输出回答

适合嵌入式、手机端低功耗场景。

5. Token 消耗与成本分析

⚠️ 不存在完全免 Token，只是消耗结构转移
  • 本地模型持续消耗：问题解析、检索词生成、网页文本解析、多轮对话全部产生 Token
  • 新增检索 Query Token：每次生成搜索词占用 Token
  • 权威知识库长文本 Token：网页/百科原文篇幅大，总 Token 可能高于内置知识模型
  • 隐性成本：在线知识库接口限流、网络延迟
场景Token 结构对比
大模型内置知识回答仅模型推理 Token回答精简，Token 少
本架构联网检索回答检索词 + 原文 + 推理 Token总 Token 可能更高，但事实准确

8. 架构优化方向

8.1 弥补 AGI 短板

🔧 两层缓存方案
  1. 本地短期记忆缓存：高频查询的常识本地轻量化向量缓存，断网时基础问题可自主回答
  2. 隐性知识蒸馏沉淀：定期将高频检索到的通用常识少量微调注入小模型，逐步内化基础知识，减少联网依赖

8.2 工程优化

  • 小模型易生成冗余检索词 → 加规则过滤减少联网开销
  • 断网丧失事实问答 → 增加本地极简常识缓存兜底
  • NPU 适配差 → 当前聚焦 CPU + 核显加速方案
